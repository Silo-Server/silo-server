# Schema standardization before 1.0

The third schema hygiene change follows the dead-table cleanup and integrity
migrations tracked in #888. It converts legacy surrogate `id` generators to
`GENERATED BY DEFAULT AS IDENTITY`, widens notification and push strings to
`text`, and renames these private storage tables:

| Previous name | Current name |
| --- | --- |
| `oauth_session` | `oauth_sessions` |
| `oauth_completion` | `oauth_completions` |
| `playback_history_admin` | `admin_playback_history` |

This requires a maintenance window. Stop **every integrated/API replica** before
starting a binary that applies these migrations. Start the remaining replicas
only with the matching binary after migrations finish. A migration advisory
lock serializes migrators; it does not stop old replicas issuing SQL. Old names
are unavailable after the rename commits, so mixed binaries break OAuth and
playback-history writes. Follow the verified-backup and recovery policy in
[release versioning](../release-versioning.md#backups-and-rollback).

The identity conversion preserves existing rows, primary and foreign keys,
sequence names, positions, and generation options. Unused sequences retain their
first value; deleted-row gaps are retained. Explicit IDs remain accepted and do
not advance the generator, just as with serial columns. Shared revision
sequences remain ordinary defaults. The conversion recreates owned sequences;
custom per-sequence grants and comments are not retained. Use the normal schema
owner for migration and verify any custom database-role arrangements separately.
Dependencies on a sequence outside its owning column prevent its removal and
abort the migration; do not bypass that refusal with `CASCADE`.

The three SQL files each run transactionally. A failure rolls back that file,
while earlier committed migrations remain applied. Goose retries pending files.
The text rollback refuses values beyond the previous caps without truncation;
resolve those values explicitly before retrying a rehearsal. SQL Down support is
for controlled migration testing and does not establish supported release
rollback. Lock duration on a production database has not been measured.

Table renames do not change native API operations, schema names, JSON fields,
Jellyfin contracts, or Apple/Android client behavior. OAuth completion encryption
continues using its fixed derivation label and `code_hash` as authenticated data.
Encrypted settings keys and notification encryption identifiers stay unchanged.
